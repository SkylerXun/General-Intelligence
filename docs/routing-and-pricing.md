# 路由与计费边界

## 一句话架构

New API 是对客户唯一可见的网关、模型目录、余额账本、消费日志和用户 API
Key 系统。Sub2API 是只供 New API 调用的内部账号池，不向客户开放。

```text
客户 SDK / 门户
       |
       v
New API: 鉴权 -> 余额预检查 -> 公开模型别名 -> 渠道选择 -> 结算
       |                              |
       |                              +--> 官方 API Key 渠道 -> 上游
       |
       +--> Sub2API 内部专用渠道 -> 账号选择 -> 单账号冷却/有限切换 -> 上游
```

这里的“路由”不是 Android 的页面跳转或交互路由。它是每个 API 请求按 API
类型、公开模型名、用户分组、可用渠道和健康状态选择后端的策略。客户只看到
稳定的公开模型别名；上游地址、账号和真实模型名不属于客户契约。

`MetaAPI` 不是这个架构中必须部署的标准组件。不同厂商可能用这个名字指代
自己的聚合 API 或元数据 API；若某个上游自称 MetaAPI，把它当作一个普通的
New API 直接渠道，先验证其鉴权方式、模型契约、计费单位、数据处理条款和
可用地域，不能因为名字相同而假定兼容。

## 渠道分层

| 上游类型 | 接入位置 | 负责的事 | 不负责的事 |
| --- | --- | --- | --- |
| 官方或商业 API Key | New API 直接渠道 | 请求转发、客户定价、用户余额结算 | 账号池轮换 |
| 已获授权的 OAuth/订阅账号 | Sub2API 账号池，再作为 New API 内部渠道 | 账号选择、刷新、单账号冷却、受限账号切换 | 客户余额、客户 API Key、对客户计费 |
| 不满足上游条款、用途或地域限制的凭证 | 不上线 | 无 | 不能用“账号池”绕过上游授权或限额规则 |

账号池的含义是同一类、可合规使用的上游账号按账号组管理其健康状态、并发、
令牌刷新和冷却。它不是给最终用户分账号，也不是第二套钱包。账号凭证只能留
在 Sub2API 的受保护数据卷和支持的导入流程中，绝不放进 New API 渠道备注、
公开模型名、截图或 Git 仓库。

## 模型与路由配置流程

每新增一个可售模型，按下面顺序完成，不能只“同步模型列表”后就上架：

1. 在 Sub2API 或 New API 先完成渠道连通性测试，并记录上游实际能力。
2. 选择一个对客户稳定的公开别名，例如 `chat-pro`；不要把账号组或临时
   上游模型名暴露在别名中。
3. 在 New API 为该别名建立映射：API 类型、真实上游模型名、渠道或分组、
   最大输出限制、是否支持流式/工具/图像等能力。
4. 为输入、输出、缓存读写、图片/音频等实际计量项设置售价和用户分组倍率。
   不能把不同计费单位的模型共用一个未经核验的价格。
5. 用管理员测试账号完成正常、流式、余额不足、上游 4xx/429/5xx 和中断测试。
6. 将渠道、账号组、公开别名、成本来源和负责人记录在变更记录中，再对外开放。

“全模型”在产品层的正确含义是“对外提供已验证且合规的多供应商模型目录”，
不是承诺所有厂商、所有模态、所有 API 版本都可用。尤其 New API 的 Sub2API
适配器应以已测能力为准；未验证的音频、rerank、批处理或厂商私有接口应保持
不可售。

## 计费权威与失败边界

客户余额和账单只以 New API 为权威。推荐顺序是：

1. New API 根据用户、公开模型和最大可能使用量进行余额预检查或预扣。
2. 请求发送到选定渠道；Sub2API 若被使用，只在内部选择符合条件的账号。
3. New API 根据实际返回 usage 结算；未使用部分释放或退款，并写入客户消费日志。
4. Sub2API 的账号用量只用于账号健康和成本对账，不能再次从同一客户扣费。

异常处理以“每个客户请求最多一次最终结算”为原则：

| 情况 | New API 客户余额 | Sub2API 行为 |
| --- | --- | --- |
| 余额不足 | 请求在上游前拒绝 | 不选账号 |
| 成功且有 usage | 依价格表结算 | 记录账号侧用量 |
| 上游在首字节前失败 | 释放预扣或按实际已知用量结算 | 可在同一账号组内进行有界切换 |
| 流式中断或 usage 不完整 | 按 New API 的已知结算/退款逻辑处理，人工抽样复核 | 标记账号异常，不直接改客户余额 |
| 无法证明是否执行成功 | 不自动跨供应商重放 | 保留请求 ID、渠道和上游证据后人工处理 |

第一期 `RetryTimes` 保持为 0，不允许 New API 自动跨渠道重试。Sub2API 的切换
必须限定在同一授权账号组、固定最大次数和冷却窗口内。一个完整账期完成对账
后，才可以针对幂等、首字节前失败的模型评估最多一次跨供应商 fallback；写入
请求 ID/幂等键、余额和成本对账测试后才可开启。

## 首期后台配置清单

以下属于 New API 后台持久化设置，不写入 Compose 环境变量：

- 系统名、Logo、页脚、服务条款、隐私说明和客服联系方式。
- 公开注册、密码注册、邮箱验证；Turnstile 开关及站点/密钥。
- 用户默认余额为 0，关闭自动赠送可消费额度。
- 用户组、倍率、公开模型、渠道映射、模型价格和最大输出限制。
- 管理员账户、人工余额调整权限和审计日志策略。

Sub2API 后台只建立内部服务用户、专用 API Key、账号组、并发和冷却策略。该
专用 Key 只在 New API 的内部渠道中使用，最小权限、可撤销且不分发给客户。
