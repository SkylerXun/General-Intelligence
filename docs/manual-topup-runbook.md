# 人工充值操作手册

## 适用范围

第一期只支持人工核验后的预充值。站内不展示个人收款二维码，不生成自动支付
订单，不根据截图自动入账，也不接收未签名的支付回调。

客户余额的唯一写入位置是 New API 管理后台的余额调整功能；Sub2API 绝不为
最终客户加余额。

## 标准流程

1. 客户通过已公布的客服渠道联系，提供 New API 账号标识、付款金额、付款时间
   和付款凭证。客服渠道应在官网条款和页脚中明确。
2. 操作员核对收款账户、金额、时间和流水号，确认款项真实到账。截图本身不能
   作为到账证据。
3. 第二名有权限的人员复核大额或异常充值；低于内部阈值的单人操作也必须留下
   审计记录。
4. 管理员进入 New API 后台，确认目标用户，再执行一次性余额增加。金额必须与
   已核实的到账金额一致；任何汇率、赠送或手续费差额要有明确规则。
5. 在后台备注或关联审计记录中写入外部流水号、客户账号、到账金额、操作人、
   复核人和时间。不要记录银行卡完整号码、身份证、支付密码或二维码原图。
6. 向客户确认到账，客户可在 New API 门户核对余额和后续消费日志。
7. 每日汇总后台余额变更与收款流水；每月将 New API 客户账单与 Sub2API 账号
   成本进行对账，二者不可相互替代。

## 拒绝与异常

- 账号不一致、金额不一致、收款未到账、重复流水号或凭证可疑：不加余额，创建
  异常记录并由客服处理。
- 加错账号：先冻结相关账号或额度，再由有权限管理员通过新的、可审计的反向
  调整处理；不能删除原审计事件或直接改数据库。
- 客户退款：遵循已公开的退款条款。退款前先核对剩余余额、已消费金额和原始
  流水，余额回退必须保留原因和关联记录。
- 任何人要求通过 SQL、Redis、浏览器开发者工具或 Sub2API 直接改余额：拒绝。

## 权限与留存

- 只给少量管理员授予余额调整权限；管理员账号启用 MFA，Sub2API 管理端另行
  使用独立强密码和 TOTP。
- 每周抽查余额调整记录，发现无外部流水号、金额异常或同一操作人高频调整时
  立即暂停该权限并审计。
- 审计记录和付款凭证按适用法律、隐私政策及财务留存要求保存，使用最小必要
  信息和受控访问。未经合规评估，不把付款凭证导入模型训练或客服以外的系统。

## 自动支付的后续门槛

只有取得合法主体和合规聚合支付商户能力后，才评估自动支付。届时必须使用由
支付服务商签名的 webhook，校验签名、订单号、金额、币种、状态、幂等键和
回调重放；支付订单、客户余额和价格表仍以 New API 为权威。个人收款码不是
自动入账方案。
